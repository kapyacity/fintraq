## Overview

FinTraQ is a client-side, offline-first Progressive Web Application (PWA) designed for personal finance tracking (`manifest.webmanifest:2-5`, `index.html:12`). It structures budgeting around the 50/30/20 rule (Needs: 50%, Wants: 30%, Savings: 20%) (`index.html:567-571`, `index.html:578`), while offering custom allocation ratios (`index.html:579-584`), multi-stream income tracking (`index.html:742-749`), loan/EMI schedule management (`index.html:824-938`), and native SVG analytical charts (`index.html:181-220`, `index.html:1265-1372`).

The system requires zero server-side application infrastructure. All application state is stored locally in the browser's `localStorage` (`index.html:589-620`, `index.html:642`). Multi-device state synchronization is accomplished via peer-to-peer (P2P) WebRTC data channels with public STUN/signaling servers (`index.html:555`, `index.html:1491-1840`), augmented by `BroadcastChannel` for instant same-browser cross-tab synchronization (`index.html:1841-1900`).

## Data Flow

### 1. Expense Entry & Budget Allocation Flow
1. **User logs expense:** User taps "+ Log" or enters expense details in `#expenseModal` (`index.html:473-482`, `1239-1263`).
2. **State update:** `saveExpense()` appends new expense `{id, cat, sub, amount, note, ts, updatedAt, deleted: false}` (`index.html:1240-1260`).
3. **Storage write:** `save()` commits entire state to `localStorage.getItem('fintraq_v1')` (`index.html:642`).
4. **Broadcast sync:** `broadcastSync()` dispatches state payload across open `BroadcastChannel` and active PeerJS WebRTC connections (`index.html:1708`, `1873-1900`).
5. **View re-render:** `render()` recalculates totals (`totToday`, `totWeek`, `totMonth`) and refreshes category budget progress bars (`index.html:999-1085`).

### 2. Loan EMI Payment Flow
1. **User triggers payment:** User taps "Pay EMI" on an active loan card in `#loanCard` (`index.html:893`).
2. **Validation & Balance update:** `payLoanEMI()` verifies month key has not already been marked paid in `loan.paidMonths`, decrements `loan.remainingAmount` by `loan.emiAmount`, and bumps `loan.updatedAt` (`index.html:896-904`).
3. **Auto-logging expense:** An expense is created under category `needs` and subcategory `Loan / EMI` (`index.html:906-917`).
4. **Sync & Render:** State is saved to `localStorage`, broadcast to peers, and UI displays success toast (`index.html:920-924`).

### 3. Cross-Device Peer Sync Flow
1. **Room initiation:** Both devices configure matching passphrase in settings (`index.html:1557-1582`).
2. **Peer connection:** Client claims an available slot (`fntrq_<hash>_a` through `e`) on `0.peerjs.com` and searches for adjacent slots (`index.html:1737-1750`, `1770-1805`).
3. **State payload handshake:** On `open`, initial state payload is transmitted via WebRTC DataChannel (`index.html:1708-1710`).
4. **LWW Reconciliation:** Receiving peer executes `reconcileStates()`, performing union by ID on expenses, loans, and incomes using `updatedAt` timestamps and tombstone checks (`index.html:1599-1662`).
5. **Persistent commit:** If changes are detected, local state is overwritten, saved to `localStorage`, and UI refreshes (`index.html:1714-1719`).
